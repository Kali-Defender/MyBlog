# 二维差分与前缀和，秒杀“棋盘”翻转

## 背景：蓝桥杯“棋盘”题的暴力破解之痛

最近在刷蓝桥杯的模拟题，遇到了一道非常经典**“棋盘”**题：

> **问题描述**：有一个 \(n \times n\) 的棋盘，初始全白（0）。进行 \(m\) 次操作，每次将矩形范围 \((x_1, y_1)\) 到 \((x_2, y_2)\) 内的棋子颜色取反（0变1，1变0）。求最终棋盘状态。
> **数据范围**：\(n, m \le 2000\)。

---

## 方法一：暴力模拟（老实人打工，必然 TLE）

最直观的思路是：每次操作，用两层 `for` 循环遍历指定的矩形区域，挨个执行 `^= 1`（异或翻转）。

```python
n, m = map(int, input().split())

# 初始化 n x n 的棋盘，全 0
grid = [[0] * n for _ in range(n)]

for _ in range(m):
    x1, y1, x2, y2 = map(int, input().split())
    
    # 遍历矩形范围内的每一个格子（坐标需减1对齐数组索引）
    for i in range(x1 - 1, x2):
        for j in range(y1 - 1, y2):
            grid[i][j] ^= 1

# 输出最终棋盘
for row in grid:
    print("".join(map(str, row)))
```

**痛点分析**：
*   老板派个任务，你就立刻去刷一遍矩形。\(m\) 个任务，就要跑 \(m\) 轮大循环。
*   时间复杂度高达 \(O(m × n^2)\)。在 \(2000\) 的数据极限下，最坏情况需要执行约 **80 亿次运算**。Python 10 秒绝对跑不完，必然 TLE。

为了解决这个问题，我们需要请出算法界的“降维打击”双星：**二维差分**与**二维前缀和**。
核心思想只有一句话：**不在矩形里反复修改，只在四个角打标记，最后统一结算（包工头思维）。**

---

## 方法二：降维打击（二维差分满分解法）

### 一图胜千言：核心逻辑图解

看看这张手稿推演图，它将**蓝桥杯题目的翻转操作**具象化了：

![差分](/img/数据结构/差分.png)

**图解拆解（以样例1的第一次操作 `1 1 2 2` 为例）：**

假设我们要翻转的目标区域是图中的**红框**。
我们在红框的**外侧（橙色框的四个角）**打上标记（代码里就是 `^= 1`）。

> 💡 **前缀和魔法规则**：在任意一点打上标记，它的影响力就会像水流一样，**向右下方无限蔓延**。

看右侧的“账本”推导：
*   **第 1 步，在左上角 `(x1, y1)` 打标记**：水流蔓延，目标区域以及右侧（一区域）、下侧（二区域）、右下角（三区域）全被翻转了 1 次（全亮）。
*   **第 2 步，在右上角外墙 `(x1, y2+1)` 打标记**：为了把多翻的“一区域”抵消掉，我们在它的起点打标记。此时一区域经历了 2 次翻转，互相抵消（`1+1=0`）。
*   **第 3 步，在左下角外墙 `(x2+1, y1)` 打标记**：同理，为了把多翻的“二区域”抵消掉。二区域也经历了 2 次翻转，抵消。
*   **第 4 步，在右下角外墙 `(x2+1, y2+1)` 打标记**：在之前的步骤中，右下角（三区域）被三次水流交汇，导致了 3 次翻转（奇数，依然亮着）。为了熄灭它，必须在右下角交叉点补上最后一击，让它变成 4 次翻转（`1+1+1+1=0`），完美抵消。

**最终结果**：唯独**目标红框**受到了 1 次翻转，保留了下来。其他区域全部被偶数次抵消。

## 【灵魂拷问 Q&A】新手最容易卡壳的 3 个问题

### ❓ Q1：为什么一定要起“外墙”（坐标 +1）？
因为**区间是包含边界的**。
如果你直接把“刹车”（抵消标记）打在目标的边界 `(x2, y2)` 上，那么边界本身也会被这个刹车抵消掉，导致目标区域最右下角的格子“漏气”变成了 0（前功尽弃）。
所以，我们必须在目标的**外面（`x2+1` 和 `y2+1` 紧紧相邻的下一个格子）**踩刹车，建立一堵外墙，把目标区域严丝合缝地包裹在里面。

### ❓ Q2：前缀和公式 `diff[i][j] ^= diff[i - 1][j] ^ diff[i][j - 1] ^ diff[i - 1][j - 1]` 怎么理解？（风向理论）
把它当成**“看风向”**。
因为我们是从左到右、从上到下扫描的，所以算当前格子时，只能接收**西边（左）**、**北边（上）**吹来的风。
*   左边的格子把状态传给了它（西风）。
*   上面的格子把状态也传给了它（北风）。
*   但**西北角（左上）**的风，同时被西风和北风各带了一次，**算重了两次（`1^1=0` 抵消了）**。为了把丢失的数据救回来，必须再异或一次左上角（补漏）。

**一句话总结**：当前状态 = 自己标记 ^ 北风 ^ 西风 ^ 西北风补漏。因为操作是 0/1 翻转，所以加法天然变成了异或（`^`）。

### ❓ Q3：底层是怎么“刮风”的？既然都是用 `for` 循环，为什么差分能秒杀暴力？
计算机底层没有魔法，纯机械。底层就是双重 `for` 循环逼着每个格子去“抄袭”左边和上边的数据。因为扫描顺序固定（前一个格子的结果被后一个格子继承），就造成了“风吹蔓延”的假象。

*   **暴力解法（老实人）**：每次接任务立刻跑 `for` 循环干活，\(m\) 个任务 = \(m\) 轮大循环。总复杂度 \(O(m \times n^2)\)。
*   **差分法（包工头）**：接任务时只在小本本上打 4 个标记（0 轮大循环，时间 \(O(1)\)）；等所有任务派完，只跑 **1 轮**大循环算总账。总复杂度 \(O(m + n^2)\)。

### Python 满分解法代码

打标记只是第一步，全部操作完成后，我们需要从左到右、从上到下扫描一遍整个矩阵，把真实的“墙”刷出来（求二维前缀和）。

```python
import os
import sys

def solve():
    # 读取 n 和 m
    n, m = map(int, input().split())

    # 建立 (n+2) x (n+2) 的二维差分数组，初始全 0
    # 为什么要 +2？因为要留出“外墙”的位置，防止 x2+1 和 y2+1 越界
    diff = [[0] * (n + 2) for _ in range(n + 2)]

    # 1. 离线处理：处理 m 次操作，只打标记（0轮大循环）
    for _ in range(m):
        x1, y1, x2, y2 = map(int, input().split())
        
        # 二维差分的“四角标记法”（因为全是翻转，用异或 ^= 1）
        diff[x1][y1] ^= 1
        diff[x1][y2 + 1] ^= 1
        diff[x2 + 1][y1] ^= 1
        diff[x2 + 1][y2 + 1] ^= 1

    # 2. 集中结算：利用二维前缀和还原整个棋盘（仅跑1轮大循环）
    for i in range(1, n + 1):
        for j in range(1, n + 1):
            # 当前格子的最终状态 = 自己的标记 ^ 上面累积的影响 ^ 左边累积的影响 ^ 左上角被重复抵消的影响
            diff[i][j] ^= diff[i - 1][j] ^ diff[i][j - 1] ^ diff[i - 1][j - 1]
            
            # 顺便直接输出当前行的结果（这样连单独输出的循环都省了）
            print(diff[i][j], end="")
        print() # 换行

if __name__ == '__main__':
    solve()
```

**复杂度分析**：
*   **时间**：打标记 \(O(m)\) + 还原矩阵 \(O(n^2)\)。总时间 **\(O(m + n^2)\)**，在 \(n=2000\) 时，Python 仅需 0.1 秒。
*   **空间**：差分数组大小 \(O(n^2)\)。

## 从运维视角看算法：延迟计算的思想

作为写运维博客的博主，我其实在这道题里看到了**运维系统设计**的影子：
*   面对频繁的“批量下发配置/标记状态”请求，如果每次都立即去轮询、修改目标节点，会对系统造成巨大压力（类似暴力 `for` 循环）。
*   而差分法提供了一种**“局部标记 -> 延迟结算”**的架构思想：我先把指令记录在日志里，在边界处做好标记（只占极小的内存开销）。等到最后统一结算时，用一次 \(O(n^2)\) 的扫描，把全局状态推平。

这种**“离线处理 -> 集中结算”**的思维，在处理大规模日志分析、分布式节点状态同步时，有着异曲同工之妙。
